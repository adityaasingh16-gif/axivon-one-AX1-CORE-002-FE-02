Shared rules: Never disclose whether an email or account exists. Use equivalent public responses for known and unknown identifiers. OTP, verification requirements, and post-registration auto sign-in are configurable. The same flow applies across clients and roles. Protected entry checks Session S1; absent or unusable session goes to Login L1.

Origin: Verification keeps Registration R1 or Password Recovery F1 as its origin. Cooldown keeps the exact interrupted step. Pending operations have success and failure exits; no failure is treated as a terminal state.

X1 · Cooldown: Origin → rate limit → timed wait → affected controls re-enabled → retry origin. Cancel always returns to Login L1 or Entry E1.

Privacy-safe confirmation: “If an account matches, we’ll send instructions.” Do not change public wording based on account existence. Field-format errors can be specific; account-status errors stay generic.
